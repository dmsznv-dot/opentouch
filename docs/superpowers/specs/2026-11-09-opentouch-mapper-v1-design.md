# OpenTouch Mapper v1 — дизайн

Дата: 2026-11-09
Статус: черновик на ревью

## 1. Цель

Лёгкая программа для проекционного маппинга — альтернатива связке TouchDesigner + Kantan Mapper / Stoner без нодовой сложности TD. v1 решает одну задачу: вывести на проектор настраиваемые поверхности и показать на них видео, при этом **вне поверхностей — абсолютный чёрный (RGB 0,0,0)**. Программа — фундамент для будущих генеративных источников (GLSL/ISF, JS-скетчи) и нодового UI.

### Критерии успеха v1

1. На реальном объекте 2–3 поверхности с видео настраиваются быстрее, чем в Kantan Mapper.
2. Ни одного ненулевого пикселя вне поверхностей — проверяется автоматическим тестом.
3. Никаких белых вспышек на проекторе при открытии, перезапуске и переподключении.
4. Инсталляция стартует без участия человека (вход в систему → последний проект → Show).

### Ограничение, которое программа не решает

Чёрный RGB 0 ≠ отсутствие света: DLP/LCD-проекторы светят и на чёрном. Это решается железом (контраст, лазерные/dynamic black модели, шторки). Keystone в самом проекторе должен быть выключен — иначе он теряет пиксели до нашей программы.

## 2. Контекст и ограничения

| Параметр | Решение |
|---|---|
| ОС | macOS (Apple Silicon / Intel) |
| Стек | Electron + TypeScript + WebGL2, UI на React |
| Проекторы | один вывод в v1; архитектура не запрещает несколько |
| Видео | H.264; HEVC — после спайка (см. §9). Без альфы. ProRes/Hap не поддерживаются |
| Сценарии | инсталляции и лайв |

### Что взято из TouchDesigner (для ориентира)

- **Kantan Mapper**: quad и freeform-формы, прямые или Безье-стороны, grid-warp внутри quad, soft edge.
- **Stoner**: двухуровневый warp — corner pin + mesh-сетка с Безье-ручками; смена rows/cols сбрасывает сетку.
- **Window COMP / Perform mode**: отдельное полноэкранное окно вывода, UI на другом экране.
- Не берём в v1: camSchnappr (3D-калибровка), projectorBlend (edge blending), нодовую сеть.

## 3. Архитектура

**Один движок на два окна.** Окно проектора открывается из окна редактора через `window.open` (same-origin) и живёт в том же renderer-процессе и JS-контексте. Отсюда:

- одна модель сцены, один набор `HTMLVideoElement` — каждое видео декодируется один раз;
- два экземпляра `Renderer` (превью в редакторе и вывод на проектор) берут кадр из одного видеоэлемента — рассинхрона нет;
- main-процесс: дисплеи, файлы, автозапуск, сторож.

Отклонённые варианты: два независимых renderer-процесса с синхронизацией через IPC (двойное декодирование, рассинхрон на 1–2 кадра); рендер только в окне вывода + стрим превью через `captureStream` (задержка, лишнее копирование, без выигрыша).

### Модули

| Модуль | Процесс | Ответственность |
|---|---|---|
| `main/displays` | main | Список дисплеев (`screen`), выбор проектора (по id + разрешению), реакция на `display-added` / `display-removed`, открытие окна вывода на нужном дисплее |
| `main/project-io` | main | Открытие/сохранение `.otproj`, автосохранение, недавние проекты |
| `main/autostart` | main | Login item, режим «последний проект → Show», сторож renderer-процесса |
| `core/model` | renderer, без DOM | Типы проекта, чистые функции изменений, команды undo/redo, (де)сериализация, версия формата |
| `core/warp` | renderer, без DOM | Гомография, интерполяция сетки (linear / Catmull-Rom / Безье), построение меша, пересэмплирование сетки |
| `sources/*` | renderer | Интерфейс `Source` + реестр. v1: `video`, `testpattern` |
| `gl/renderer` | renderer | Отрисовка проекта в viewport; кэш мешей и масок |
| `ui/*` | renderer | Редактор (React) |

`core/*` не зависит от DOM, WebGL и Electron — тестируется в Node.

### Интерфейс источника (точка расширения)

```ts
interface Source {
  readonly id: string;
  readonly width: number;
  readonly height: number;
  /** Вызывается раз за кадр вывода; возвращает true, если текстура обновлена. */
  update(gl: WebGL2RenderingContext, tex: WebGLTexture, timeSec: number): boolean;
  dispose(): void;
}

interface SourceFactory<P> {
  type: string;                        // 'video' | 'testpattern' | позже 'isf' | 'sketch'
  defaults(): P;
  create(params: P, ctx: SourceContext): Source;
}
```

Источник рисует в текстуру — так же, как TOP в TD. Будущий нодовый UI — это граф `Source → Effect → Surface` поверх того же интерфейса; в v1 граф вырожден до «источник → поверхность».

## 4. Модель данных

```ts
type Vec2 = { x: number; y: number };

interface Project {
  version: 1;
  output: { displayHint?: { id: number; width: number; height: number }; width: number; height: number };
  sources: SourceDef[];
  surfaces: Surface[];               // порядок массива = z-order (последний сверху)
}

interface SourceDef {
  id: string;
  name: string;
  type: 'video' | 'testpattern';
  params: VideoParams | TestPatternParams;
}

interface VideoParams { path: string; loop: boolean; rate: number; muted: boolean }  // path относительно файла проекта
interface TestPatternParams { pattern: 'grid' | 'checker' | 'corners' }

interface Surface {
  id: string;
  name: string;
  visible: boolean;
  opacity: number;                    // 0..1
  sourceId: string | null;            // null → поверхность чёрная
  inputRect: { x: number; y: number; w: number; h: number };  // вырезка из источника, 0..1
  corners: [Vec2, Vec2, Vec2, Vec2];  // уровень 1: TL, TR, BR, BL в координатах вывода 0..1
  grid: GridWarp | null;              // уровень 2
  masks: Mask[];
}

interface GridWarp {
  cols: number; rows: number;         // число ячеек; точек (cols+1)*(rows+1)
  offsets: Vec2[];                    // смещения точек в локальных (u,v) координатах quad
  mode: 'linear' | 'smooth' | 'bezier';
  handles?: Vec2[];                   // только для 'bezier': по 4 ручки на точку (±u, ±v), в (u,v)
}

interface Mask {
  id: string;
  mode: 'include' | 'exclude';
  points: Vec2[];                     // замкнутый полигон, координаты вывода 0..1
  feather: number;                    // px вывода
}
```

### Правила

1. **Двухуровневый warp.** Точка рендера = `H(corners) · (uv + gridOffset(uv))`. При перемещении углов сетка следует за ними, тонкая подгонка сохраняется.
2. **Смена rows/cols** пересэмплирует текущую форму сетки в новую (в отличие от TD, где сетка сбрасывается).
3. **Маски — в координатах вывода**, не поверхности. Видимая область поверхности = (объединение include, либо весь вывод, если include нет) минус объединение exclude.
4. **Нормализованные координаты** 0..1 — проект переживает смену разрешения. Шаг стрелки 1 px пересчитывается из `output.width/height`.
5. **Один источник — много поверхностей.** Это даёт режим «общего холста»: соседние поверхности показывают соседние `inputRect` одного видео синхронно.
6. **Дублирование поверхности** — глубокая копия, сдвиг на 0.02 по x и y, тот же `sourceId`, новые id.
7. Удаление источника, используемого поверхностями, ставит у них `sourceId = null`.

### Файл проекта

`.otproj` — JSON (UTF-8, с отступами, чтобы diff в git был читаемым). Пути к медиа хранятся относительно файла проекта; при отсутствии — поиск по имени в папке проекта, затем предложение перепривязать.

## 5. Рендер-пайплайн

**Такт.** Главный цикл — `requestAnimationFrame` окна вывода (vsync проектора). Превью в редакторе — своё `rAF`, ограничено 30 fps.

**Кадр вывода:**

1. **Источники.** Видео загружается в текстуру только при новом кадре (`requestVideoFrameCallback`). Тестовые паттерны генерируются один раз.
2. **Очистка** в `(0,0,0,1)`. Контекст создаётся с `alpha: false`, `antialias: true`.
3. **Поверхности по z-order.** Для каждой видимой поверхности с источником:
   - **меш** из кэша (перестраивается при изменении `corners`/`grid`/`inputRect`): сэмплы (u,v) с плотностью 32 подразделения на ячейку сетки → смещение сетки → гомография → координаты вывода; UV = `inputRect` ∘ (u,v). Quad без сетки = сетка 1×1;
   - **маска** — текстура R8 размера вывода из кэша (перестраивается при изменении масок): растеризация полигонов (include-union, затем exclude) + сепарабельный gaussian blur с радиусом `feather`. Поверхности без масок используют общую белую 1×1 текстуру;
   - **шейдер**: `color = texture(src, clampToInputRect(uv)) * mask(fragCoord) * opacity`, смешивание over (premultiplied). `clampToInputRect` сжимает UV внутрь `inputRect` на полтекселя — без просачивания соседних пикселей источника.
4. **Оверлей** (только в Edit): линии меша, контрольные точки, выделение, контуры масок. Тумблер «тестовая сетка вместо контента» — для выбранной поверхности или для всех.

**Гарантии чёрного:**

- `BrowserWindow` вывода: `backgroundColor: '#000000'`, `show: false` до `ready-to-show` — иначе белая вспышка;
- `html, body { background: #000; cursor: none; margin: 0; overflow: hidden }` в окне вывода;
- окно вывода в simple fullscreen на дисплее проектора, без рамки, меню и Dock на этом экране;
- видео без `loop` по окончании держит последний кадр;
- источник в состоянии ошибки или загрузки → поверхность рисуется чёрной (не пропадает, не мигает).

**Режимы.** Edit: на проекторе контент + оверлей. Show: на проекторе только контент; оверлей и ручки остаются в превью редактора — можно подстраивать во время шоу. Переключение `Tab`.

**Целевая производительность** (проверяется на железе, не гарантируется): 1080p60 на Apple Silicon, 10 поверхностей, 2 одновременных видео 1080p.

**Известное узкое место:** кадр видео загружается в GPU дважды (по разу на каждый WebGL-контекст). Митигация в v1 — превью 30 fps. Запасной вариант, если не хватит: превью копирует готовый кадр вывода (`drawImage` canvas → canvas) вместо собственного рендера.

## 6. UI редактора

**Раскладка:**

- **Верхняя панель:** выбор дисплея проектора, Edit/Show, тест-сетка, play/pause, имя проекта и статус сохранения.
- **Левая панель:** список поверхностей (добавить, дублировать, удалить, видимость, drag для z-order); под ним список источников (добавить видео — диалог или drag-n-drop файла; добавить тестовый паттерн).
- **Центр:** вьюпорт, две вкладки — **Output** (пространство проектора: точки, сетка, маски) и **Input** (кадр источника выбранной поверхности: рамка `inputRect`).
- **Правая панель (инспектор):** для поверхности — источник, opacity, rows/cols, режим сетки, список масок (mode, feather); для видео — loop, rate, звук (по умолчанию выключен).

**Взаимодействие:**

| Действие | Ввод |
|---|---|
| Двигать точку | drag точки |
| Двигать поверхность целиком | drag внутри поверхности |
| Множественное выделение точек | Shift-клик, рамка |
| Тонкая подгонка | стрелки — 1 px, Shift+стрелки — 10 px |
| Уровень редактирования | `G`: углы ↔ сетка |
| Рисование маски | `M`: клики ставят точки, клик по первой — замыкает |
| Дублировать / удалить | `⌘D` / `⌫` |
| Undo / redo / save | `⌘Z` / `⇧⌘Z` / `⌘S` |
| Edit/Show, тест-сетка, play/pause | `Tab`, `T`, `Space` |
| Прилипание к точкам других поверхностей (8 px экрана) | вкл. по умолчанию; `S` — выкл. |

Управление — только из редактора; мышь на проекторе не используется.

## 7. Обработка ошибок и надёжность

| Ситуация | Поведение |
|---|---|
| Медиафайл не найден | источник `missing`, поверхности чёрные, предложение перепривязать (сначала поиск в папке проекта) |
| Кодек не поддерживается (`error` у `<video>`) | сообщение «перекодируйте в H.264», поверхности чёрные |
| Проектора нет при старте | статус «ожидание дисплея»; окно вывода открывается автоматически при появлении (сначала по сохранённому id, иначе любой не основной дисплей) |
| Проектор отключили во время работы | окно вывода закрывается; при возврате — открывается заново в прежнем режиме |
| `webglcontextlost` | пересоздание рендера, повторная загрузка текстур при `webglcontextrestored` |
| Падение renderer-процесса | main перезапускает окна, открывает последнее автосохранение, восстанавливает режим |
| Файл проекта новее поддерживаемой версии / повреждён | отказ открыть с понятным сообщением; файл не перезаписывается |

**Автосохранение:** каждые 30 с при наличии изменений, ротация 5 последних копий рядом с проектом (`.otproj.autosave.N`).

**Автозапуск:** опция в настройках — login item; при старте открывает последний проект, ждёт дисплей, включает Show.

## 8. Тестирование

| Уровень | Инструмент | Что проверяется |
|---|---|---|
| Юнит | Vitest | гомография на известных точках; пересэмплирование сетки; точность меша (отклонение < 0.5 px при 1080p относительно точной перспективы); команды undo/redo; сериализация ↔ десериализация |
| Рендер | Electron + Playwright, `readPixels` | **все пиксели вне поверхностей = 0,0,0**; маски include/exclude; отсутствие просачивания за `inputRect`; эталонные кадры с допуском |
| E2E | Playwright `_electron` | создать проект → добавить поверхность → дублировать → сохранить → открыть заново |
| Ручной | чек-лист | на реальном проекторе: нет белой вспышки, переподключение кабеля, Show без курсора, автозапуск |

Разработка — TDD для `core/*`.

## 9. Открытые вопросы, закрываемые в начале реализации

1. **Спайк HEVC:** воспроизводит ли выбранная версия Electron HEVC через `<video>` на macOS с аппаратным декодированием. Результат фиксируется в этом документе. Если нет — v1 поддерживает только H.264.
2. **Спайк `window.open`:** подтвердить, что дочернее окно same-origin в выбранной версии Electron даёт прямой доступ к DOM и что WebGL-контекст на его canvas работает с видеоэлементом из окна-родителя. Если нет — возвращаемся к выбору архитектуры.

## 10. Вне v1
